# CLAUDE.md — Sketchforge

Instructions de passation pour Claude Code. À lire avant toute modification.

## 1. Contexte (important)

- Sketchforge est une application de dessin et d'animation (inspirée de Clip Studio et d'Adobe Animate, avec du code 100 % original). Elle tourne dans le navigateur ou en PWA, avec Electron pour le bureau.
- **Restauration du 17/11/2026** : ce dépôt part du dernier instantané disponible, **v2.0.0 (17/11/2026, 02:36)**. Une version plus récente, développée dans une session Claude, a été perdue. Son contenu est **inconnu** : il ne faut **pas** inventer ces fonctionnalités. Elles seront redécrites par l'utilisateur et réimplémentées une par une (voir § 7).
- L'utilisateur est francophone mais souhaite des réponses en anglais. Code et commentaires en anglais.

## 2. Lancer

```bash
python3 build.py              # parts/*.js -> app.js + node --check (OBLIGATOIRE après toute modif JS)
python3 -m http.server 8000   # puis http://localhost:8000 (le service worker exige http)
npm install && npm start      # bureau (Electron)
npm run dist                  # installeurs (electron-builder)
```

`index.html` s'ouvre aussi en `file://`, mais sans service worker (et le 3D peut être bloqué selon le navigateur).

## 3. Architecture

Il n'y a ni bundler, ni framework, ni dépendance runtime. Un seul script global :

| Fichier | Rôle |
|---|---|
| `parts/p*.js` | **Source.** Concaténés par ordre alphabétique de nom de fichier. L'ordre compte : les fichiers partagent la portée globale (`state`, `compositeFrame`, …). |
| `app.js` | **Généré** par `build.py`. Ne jamais l'éditer à la main. Il est versionné pour que l'app tourne sans étape de build. |
| `index.html` | DOM (menus, panneaux, palettes), charge `style.css?v=…` et `app.js?v=…`. |
| `style.css` | Tout le style. |
| `three3d.js` | Bundle three.js (MIT, voir `THREE-LICENSE.txt`), chargé **à la demande** par `load3D()` (p10y). Expose `SF3D`. |
| `vroid3d.js` | **Généré** par `tools/build_vrm.py female.vrm male.vrm` (Pillow) depuis les modèles VRoid de l'utilisateur (auteur « bluegi », qui a autorisé la redistribution et la modification dans Sketchforge ; les originaux ne sont pas dans le dépôt) : .glb allégés (sans morph targets, spring bones, vignette ; textures ≤ 1024 px) en base64, `SF_VRM`. Chargé à la demande avec `three3d.js`. Ne pas éditer à la main. |
| `models3d.js` | **Généré** par `tools/build_models.mjs` depuis `assets/HumanLowPolyBaseMesh.fbx` : mannequins homme / femme riggés (16 joints, mesh quantifié, poids de skin), chargé à la demande après `three3d.js`. Expose `SF_MODELS`. Ne pas éditer à la main. |
| `sw.js` | Service worker network-first, cache `sketchforge-vXXX`. |
| `cloud-config.js` | Valeurs **publiques** en ligne : adresse du site (Netlify), URL + clé anon Supabase. Vide = tout marche hors ligne. Lu aussi par `main.js` (adresse du site pour les mises à jour). |
| `cloud-lib.js` | Client Supabase sans dépendance (auth OAuth Google/GitHub, REST, Storage, fonction `ask`), partagé par l'app et le site. Expose `SFSB`. |
| `site/` | Site officiel (accueil, `account.html`, `link.html` = connexion des apps installées par code à usage unique). `tools/build_site.mjs` → `dist-site/` (site + app web dans `/app/` + `version.json` + `_headers`), publié sur **GitHub Pages** (https://akarulvm777.github.io/Sketchforge/, job `pages` du workflow, seulement sur les releases ; le dépôt est public depuis le 18/11/2026). Netlify (`netlify.toml`) reste une alternative. **Référencement** : `site/robots.txt`, `site/sitemap.xml`, lien canonique + JSON-LD `SoftwareApplication` dans `site/index.html`, `noindex` sur account / profile / link ; clé IndexNow `site/<clé>.txt` (publique), envoyée par le job `pages` après chaque mise en ligne (Bing, Yandex…). Google : Search Console par l'utilisateur (balise de vérification à ajouter dans `site/index.html`). |
| `site/community.html`, `shared.html`, `profile.html` | Social (parties communes : `site/assets/social.js`). **Community** = avis et idées (`comments` sans `item_id`, `rating` 1–5). **Shared** (`shared.js`) = tous les partages, choix Art / Outils (`#art` / `#tools`), tri, partage avec « fait moi-même / ailleurs + crédit » (`shared_items.origin`, `credit`), 👍 / 👎 (`reactions`), 🔁 repartage (`reshare_of`, même fichier), commentaires, téléchargement. **Profile** (`profile.js`, `?u=<uid>`) = nom, photo (256 px dans `shared/<uid>/avatar-…`), bio, site (`profiles`), et les partages de la personne ; modifiable par son propriétaire. Bucket public `shared` (100 Mo). Tables / règles / droits : `supabase/setup.sql` sections 5–7 (les nouveaux projets Supabase n'ont pas les GRANT automatiques). |
| `supabase/` | `setup.sql` (tables, RLS, buckets, RPC). Mode d'emploi : `docs/ONLINE-SETUP.md`. |
| `main.js` | Coquille Electron (contextIsolation, sandbox, dialogue « modifications non enregistrées »). |
| `tools/smoke.py` | Test de fumée headless (Playwright). |
| `tools/build_models.mjs` | Génère `models3d.js` (`npm install` puis `npm run build:models`). Les repères des joints et les rayons des os sont en haut du fichier. |

Modules dans `parts/` :

- `p00_head` : état global, utilitaires.
- `p02_layers` : calques, cels.
- `p02b_blend` : modes de fusion des calques. `BLENDS` (p00, 28 modes dans l'ordre habituel), `BLEND_LABEL` (noms affichés). Les modes natifs passent par CSS `mix-blend-mode` / `globalCompositeOperation` ; les autres (`isCustomBlend` : linear burn, subtract, glow dodge, add, add (glow), vivid / linear / pin light, hard mix, darker / lighter color, divide) par `blendCustom(g, src, mode)` pixel par pixel : à l'écran une vue cuite « calques du dessous + ce calque » (`customBlendView`, depuis `refreshStage`, rafraîchie après chaque modif par `refreshCustomBlends`), dans `compositeFrame` (`opts.until` / `opts.view`), la fusion vers le bas et la pipette ; aperçu du trait en cours avec le mode natif le plus proche (`cssBlend`). PSD : `PSD_BLEND` (p10p). **Performance** : le rendu « calques du dessous » est gardé (`l._below`, clé `cbBelowKey`) ; un trait ne refait que sa zone (`CB_DIRTY`, rempli par `celEntry` via `cbMarkDirty`, `blendCustom(g, src, mode, r)`) ; rien n'est refait si ni ce calque ni le dessous n'a changé (`l._bvSelf`). Test : `blendtest`.
- `p03_history_view` : undo/redo, vue (zoom, rotation, flip).
- `p04_brush` : moteur de pinceau, pression, stabilisateur.
- `p05_selection` : sélections.
- `p06_transform` : outil Move, transformations, tweens.
- `p07_ui` : palettes, propriétés d'outil.
- `p08_ops` : commandes.
- `p09_timeline` : timeline, onion skin, lecture.
- `p10_docs_export` : save/open `.sketchforge`, exports GIF, WebM, PNG et ZIP.
- `p10o_multidoc` : plusieurs documents (onglets). Le document actif vit dans les globales (`state` pour les champs de `DOC_FIELDS`, `history`, `view`, `sel`, `layerSeq`, `layerCounter`, `dirty`, `TL.frames`, `aud`, `lightPins`) ; les autres sont rangés dans `rec.saved` (`docStash` / `docLoad`). `newDocument` et `openDocumentFile` appellent `docPrepareNew()` (nouvel onglet, sauf l'onglet vierge de démarrage). **Si tu ajoutes un état propre au document dans un autre module, ajoute-le à `docStash` / `docLoad` / `docBlankGlobals`.** Aussi : déplacer un document dans une nouvelle fenêtre (postMessage `sf-ready` / `sf-doc` / `sf-loaded`), et la « seconde vue » (vue live flottante, détachable dans une fenêtre).
- `p10ob_session` : « se souvenir du dernier travail » : quelques secondes après chaque changement (et au changement d'onglet / en quittant), tous les documents ouverts sont sauvés dans IndexedDB `sketchforge-session` (onglet actif, frame, vue, non-sauvé) et rouverts au démarrage. `buildDocObject(src, {cache})` sérialise n'importe quel onglet ; les PNG des cels sont mis en cache tant que `cel._sv` ne change pas (incrémenté par `acquireCel`, undo/redo de `celEntry`, `pupRender`). **Si tu modifies les pixels d'une cel sans `acquireCel`, incrémente `cel._sv`.**
- `p10oc_autosave` : **auto-save** (`AUTO`, `sketchforge.autosave.v1` : on, min = 5) : `autoSaveTick` toutes les 10 s → `autoSaveDue` (pure : modifié, calme `inputQuiet(5000)`, rien en cours, minutes passées) → `autoSaveNow` : fichier choisi par File › Save via `showSaveFilePicker` (poignée `DOCS.cur.handle`, réécrit en place, `writeHandle`), sinon app Android / iPad (`nativeSave`), sinon copie de session (`sessionSave`). `saveDocument` enveloppé : poignée → réécrit ; `canPickSave` (désactivé dans `harness.cjs` par `sketchforge.savepick.v1 = off`, donc les tests gardent le téléchargement). Statut `#autoSaveStat`. Test : `autosavetest`.
- `p10p_anim` : light table, audio, page manager, export PSD, bouton 3D.
- `p10pa_reuse` : réutiliser des dessins : copier / coller le dessin d'un calque (Alt+C / Alt+V), répéter des frames (cycles), bibliothèque de dessins (IndexedDB `sketchforge-library`, partagée entre documents).
- `p10pb_rig` : rigging. Bone rig = parentage de calques (`l.parent` = id du parent) : la matrice complète d'un calque est `layerMat(l, f)` (p02) = matrice du parent × sa propre transformation de keyframe. **Pour dessiner / transformer un calque, utilise `layerMat` (ou `xfCss`, qui en tient compte), pas `xfMatrix` seul.** Le pivot du calque est l'articulation. Overlay des os dans l'outil Move (`drawBones`). Puppet warp : sous-outil `puppet` du groupe Move ; une cel de keyframe porte `c._pup = { rest, pins, cur }` (dessin d'origine + épingles au repos / posées) et est recalculée par `pupRender` (MLS rigide sur une grille, triangles texturés). `copyCel` copie `_pup` ; les épingles sont sauvées (`cels[].pup`, `doc.pupRests`).
- `p10pc_animplus` : animation « un seul calque » : dessiner sur une frame tenue / vide crée un **nouveau dessin vierge** (`ANP.newKey` 'blank' / 'copy' / 'off', via `animNewBlank` appelé par `acquireCel` de p03), bouton « ＋ New drawing » (Shift+→, exposition on 1s/2s…), menu clic droit de la timeline, glisser la keyframe sélectionnée (Alt = copie), double-clic = nouveau dessin, play range (`state.playIn/playOut`, dans `DOC_FIELDS`), ping-pong, réglages onion (`ANP`, défini dans p08 avec `updateOnion` / `playRange`), export sprite sheet / fond transparent / plage. Préférences : `sketchforge.anim.v1`. Premier passage en Animation : question « first time? » (`animIntro` dans p10zx, clé `sketchforge.animintro.v1`).
- `p10pd_swap` : dessins de remplacement (main ouverte / fermée, yeux) : `l.swaps = [{ id, name, cel }]` par calque, barre `#swapBar` au-dessus de la timeline (mode Animation, rendue par `renderSwapBar`, crochets sur `renderTimeline` et `setMode`). `swapUse` crée une keyframe en gardant `_xf` ; `cel._swap` = dessin utilisé ; ⟳ Update everywhere (`swapUpdate`) ; Alt+] / Alt+[. Sauvés : `layers[].swaps`, `cels[].swap`. Test : `swaptest`.

## 4. Règles de travail

0. **Branches** (demandé par l'utilisateur le 20/11/2026) :
   - `dev` : nouvelles fonctions et corrections. La branche de session Claude est poussée sur `dev` (fusion).
   - `prerelease` : nettoyage avant une version (architecture, noms, pas de duplication, documentation). On y fusionne `dev` quand les fonctions prévues marchent.
   - `master` : le code de la **dernière version publiée**, rien d'autre. **Jamais de push direct** : on fusionne `prerelease` par une pull request, seulement quand les tests passent (le workflow les lance sur la PR). Une version de `package.json` sans tag sur `master` = publication automatique de la Release.
   - Après chaque version : copier `master` sur `dev` (et `prerelease`) pour repartir d'une base propre.
1. Modifie `parts/`, puis lance `npm test` (build + contrôles de version + tests unitaires + smoke), puis commit. Une modification = un commit, avec `app.js` régénéré dans le même commit. Avant une version : aussi `npm run test:e2e` (suite complète).
2. **Release** : bumpe la version de façon cohérente aux 4 endroits suivants :
   - `package.json` → `version`
   - `index.html` → `<title>`, `?v=` sur `style.css` et `app.js`, texte de la barre d'état
   - `sw.js` → `CACHE` (sinon les PWA installées gardent l'ancien code)
   - `CHANGELOG.md` → une section `## X.Y: titre` avec des lignes `- …` (la plus récente en haut). **`README.md` ne contient que la présentation du projet** (pas d'historique, pas de numéro de version) ; `tools/tests/test_release.py` le vérifie.
   - Installeurs : `.github/workflows/build.yml` construit .exe / .dmg / .AppImage (electron-builder) et l'APK Android (Capacitor, `tools/build_www.mjs` + `tools/android_icons.sh`). Les tags ne passent pas par le proxy : un commit dont la **première ligne** du message contient `[build]` lance une build de test (toute branche). La Release GitHub `v<version>` est publiée **uniquement** quand `master` reçoit une version sans tag ; ses notes viennent de `CHANGELOG.md` (`tools/release_notes.py`). Actions › Build apps › Run workflow avec `fix_notes` réécrit les notes de toutes les releases existantes. Chaque build attend le job `test`.
   - **Clé de signature Android** : secret GitHub `ANDROID_KEYSTORE` (keystore PKCS12 en base64, alias `androiddebugkey`, mots de passe `android`, écrite comme `debug.keystore` avant `assembleDebug`). Sans elle, chaque APK a une clé aléatoire et ne s'installe pas par-dessus l'ancienne. **Ne jamais la mettre dans le dépôt (public).**
   - Historique : `build.py` injecte aussi `APP_HISTORY` (toutes les sections `## X.Y` de `CHANGELOG.md`, lues par `tools/changelog.py`, regroupées, avec dates tirées de l'historique git de `package.json`, gardées dans `release-dates.json` à committer) ; What's new les affiche sous « Earlier updates », et `version.json` (`history`) pour le site.
   - Notes de version : `build.py` injecte `APP_CHANGES` (sections `## X.Y: …` de `CHANGELOG.md` pour la version courante) : popup « What's new » au premier lancement d'une nouvelle version (`whatsNew`, clé `sketchforge.lastver`) et section du site.
   - Avant une release, si l'interface a changé : `node tools/make_screenshots.cjs` (images du site). Une release met à jour toutes les apps installées (≥ 2.4.0) via le site ; si une version a besoin d'une nouvelle app installée (main.js, Capacitor), monte `sketchforge.minShell` dans `package.json`.
3. Si tu ajoutes un fichier que l'app charge, ajoute-le aussi à `ASSETS` dans `sw.js` **et** à `build.files` dans `package.json`.
4. Interdit : ajouter une dépendance runtime ou un bundler sans accord de l'utilisateur. Le projet doit rester un dossier statique ouvrable tel quel.
5. Aucun asset, code ni nom de marque de Clip Studio ou d'Adobe. Les fichiers `.sut` et `.lmtl` sont lus uniquement via l'import utilisateur.
6. Ne recrée jamais `app.js` depuis une sortie d'outil tronquée : regénère-le toujours via `build.py`.

## 5. Tests

- **`npm test`** (à lancer avant chaque commit poussé) : `build.py`, `tools/tests/test_release.py` (Python unittest : version identique dans package.json / index.html / sw.js / app.js / release-dates.json, section de `CHANGELOG.md`, README sans historique, `app.js` à jour, fichiers chargés empaquetés), `tools/tests/unit.cjs` (tests unitaires des fonctions pures dans la vraie app : formules de fusion, courbe de pression, keyframes, matrices, CRC / zip, lecteurs .sut / tar / TIFF, QuickShape, curseurs de visage… ; ils s'exécutent dans la portée de l'app via `__sketchforge.scope`), puis `tools/smoke.py`. **Une nouvelle fonction pure = un test dans `unit.cjs`.**
- `npm run test:e2e` = suite navigateur complète ; `npm run test:all` = les deux. Le workflow lance `npm test` à chaque push, et la suite complète sur `prerelease`, `master` et les pull requests.

- `python3 tools/smoke.py` charge l'app, trace un trait, ouvre le panneau 3D, et échoue sur toute erreur JS non capturée ou si three.js ne se charge pas. Capture d'écran : `tools/smoke.png`. Si besoin, définis `CHROME_PATH` pour pointer vers un Chrome existant.
- **Suite navigateur complète** : `bash tools/e2e/run_all.sh [dossier]` (Node + Playwright ; génère les fichiers de test avec `make_fixtures.sh` : ffmpeg, ImageMagick, Pillow, psd-tools). Un fichier par fonctionnalité (`symtest`, `mdtest`, `psdtest`, `pentest`, `rigtest`…) et `toolsweep.cjs` qui essaie **chaque outil de la palette** (encre, effacement, remplissage, undo, 0 erreur JS). `harness.cjs` expose `pg.d2c` (coordonnées document → écran), `pg.strokeDoc`, `pg.inkAt`. L'app expose ses internes aux tests via `window.__sketchforge`.
- `cloudtest` simule Supabase et le site (connexion, cloud, synchro, partage, aide ✨ Ask, carte de mise à jour, site, connexion des apps par code). `electrontest` lance la vraie app Electron (sous `xvfb-run`) : chargement `sfapp://`, mise à jour en direct, redémarrage, retour aux fichiers intégrés si la mise à jour est cassée.
- **Mémoire (2.13.6, iPad)** : Safari iOS vide les canvas (calques « effacés ») ou recharge la page au-delà de ~256–384 Mo de canvas. Une étape d'annulation de pixels (`celEntry`) garde **une seule** copie et l'échange avec le calque (`swap`), avec `bytes` ; `pushHistory` respecte `HISTORY_BYTES` (120 Mo mobile, 700 Mo bureau). Les canvas d'aide (onion, ants, snap, raw, tmp) ne sont pleine page que pendant leur usage (`docSize(c, besoin)`, p02) ; seul `bufCanvas` reste dans `DOC_CANVASES`. Ne jamais créer de canvas pleine page permanent.
- **Performance (2.11.4, iPad)** : ne jamais appeler `viewport.getBoundingClientRect()` directement → `vpRect()` (p00, mesuré une fois par frame) ; le texte de position de la barre d'état est mis à jour par `statusPosAt` (une fois par frame). `beginStroke` ne copie toute la cel dans `snapCanvas` que pour les gommes et les outils directs (blend / mélange) ; sinon « before » = `crop(t.cel, b)` juste avant de valider. Dans les fonctions de zone (`clipSync`, `eraseRegion`, `texSync`), toujours `drawImage(src, b.x, b.y, b.w, b.h, b.x, b.y, b.w, b.h)`, jamais une image pleine page coupée par un clip. Ne jamais redimensionner directement depuis une cel pleine page (`smudgeStamp` copie d'abord la zone 1:1 dans `st.grab`). Le bord aquarelle floute une copie réduite. Time-lapse et sauvegarde de session attendent `inputQuiet(ms)` (`lastInputAt`, p00).
- **Performance (2.5)** : sur téléphone / grandes pages, ne jamais faire de travail plein format pendant ou juste après un trait. Les tampons de trait ne sont vidés que sur la zone utilisée (`clearBuffers(st)`, `bufClean`) ; le time-lapse rend à la taille de l'écran (`compositeFrame(f, { scale })`) quand l'app est inactive ; la sauvegarde de session encode en arrière-plan (`celURLAsync`, `toBlob`). Les traits passent par une courbe Catmull-Rom (`curveTo` / `crSegment`, puis le stabilisateur `emitPoint`) : points espacés ≠ polygone (`smoothtest`).
- Textures de pinceau : appliquées au trait entier (`texSync` dans p04 : trait brut × texture), pas à chaque tampon ; les gommes utilisent une version à bord net (`texHardFor`). `registerTexture` transforme une image en texture (menu Paper › Load image…, textures des `.sut`).
- Avant une release, faire une vérification manuelle : outils de dessin, undo/redo, calques, timeline et tween, save/open `.sketchforge`, export GIF et PNG, panneau 3D, panneaux flottants.
